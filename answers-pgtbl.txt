Answer 1:
The pgtbltest page table dump displays how the virtual address (VA) space of a user program is translated to physical addresses (PAs), including the access permission bits for each mapped page. The lower virtual addresses (0x0–0x4000) correspond to the program’s text and data regions. These entries show proper mappings to physical memory (e.g., VA 0x0 mapped to PA 0x87F22000) with permission value 0x5B, indicating that the page is valid and allows user access, reading, writing, and execution. These pages hold the program’s instructions, global data, and possibly part of the heap. The virtual pages from 0x5000 to 0x9000 have no valid page table entries (PTE = 0), meaning those addresses are currently not mapped. Near the highest part of the user space, there are two important pages set up by the kernel for every process. The address 0x3FFFFFE000 is mapped to PA 0x87F42000 with permissions 0xC7 — this is the trapframe page, storing a process’s register state during interrupts and system calls. The final entry at VA 0x3FFFFFF000 maps to PA 0x80006000 with permissions 0x4B — this is the trampoline page that contains code used during transitions between user mode and kernel mode. Overall, the displayed mappings show that user code, data, and stack reside at lower addresses, while the trapframe and trampoline pages occupy the top of the user virtual memory layout.

0x0000000000000000 → pte 0x...5B
This is a user code page with read and execute permissions (valid and user-accessible). It corresponds to the program’s text segment shown in the page table output.

0x0000000000001000 → pte 0x...5B
Another user page for code or data with the same permissions as above.

0x0000000000002000 → pte 0x...D7
A writable user page used for data or stack (valid, readable, writable, user-accessible, and dirty).

0x0000000000003000 → pte 0x...07
A page mapped only for kernel access (valid, readable, writable but not accessible from user mode).

0x0000000000004000 → pte 0x...D7
Another user data/stack page with the same writable and user-accessible permissions.

0x0000003fffffd000 → pte 0x...13
This is the USYSCALL page used for fast system call access like getpid(). It is user-readable but not writable.

0x0000003fffffe000 → pte 0x...C7
This page is the trapframe where the kernel saves user registers during traps (kernel RW, no user write permission).

0x0000003ffffff000 → pte 0x...4B
This is the trampoline page containing the shared transition code for entering and exiting user mode (readable and executable).
